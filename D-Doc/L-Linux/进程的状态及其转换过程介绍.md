在操作系统中，进程是资源分配和调度的基本单位，其状态会随着系统调度和自身身行为不断变化。通常，进程有以下**五种种基本状态**，以及明确的转换规则：


### 一、进程的5种基本状态
1. **运行态（Running）**  
   - 进程正在CPU上执行指令，占有CPU资源。  
   - 在单CPU系统中，同一时刻只有**一个**进程处于运行态；多CPU系统中，运行态进程数不超过CPU核心数。

2. **就绪态（Ready）**  
   - 进程已具备运行条件（如所需资源已分配），但尚未获得CPU使用权，等待被调度。  
   - 系统中可能有多个就绪态进程，通常被放入**就绪队列**中排队。

3. **阻塞态（Blocked）**  
   - 进程因等待某一事件（如I/O操作完成、信号量触发、等待其他进程数据）而暂时无法运行，即使分配CPU也不能执行。  
   - 阻塞态进程会被放入**阻塞队列**，等待事件发生后唤醒。

4. **创建态（New）**  
   - 进程刚被创建，正在申请系统资源（如内存、PCB控制块），尚未进入就绪态。  
   - 当资源分配完成且初始化完毕后，进入就绪态。

5. **终止态（Terminated）**  
   - 进程完成任务或因错误终止，系统正在回收其占用的资源（如内存、打开的文件）。  
   - 资源回收完成后，进程彻底消失。


### 二、进程状态转换过程（核心规则）
进程状态转换由操作系统内核（如调度程序、中断处理程序）控制，常见转换场景如下：

1. **就绪态 → 运行态**  
   - 触发条件：操作系统调度程序选择就绪队列中的一个进程，将CPU分配给它。  
   - 例：正在运行的进程时间片用完（抢占式调度），或主动放弃CPU（如调用`yield()`），调度程序从就绪队列中选一个进程运行。

2. **运行态 → 就绪态**  
   - 触发条件：  
     - 进程的时间片用完（被系统强制剥夺CPU）；  
     - 有更高优先级的进程进入就绪态（抢占式调度中，低优先级进程被中断）。  
   - 例：进程A运行时，高优先级进程B就绪，系统暂停A，将A放回就绪队列，运行B。

3. **运行态 → 阻塞态**  
   - 触发条件：进程执行过程中需要等待某事件（主动放弃CPU）。  
   - 例：进程发起磁盘I/O请求、等待用户输入、申请互斥锁未获得时，进入阻塞态，等待事件完成。

4. **阻塞态 → 就绪态**  
   - 触发条件：进程等待的事件完成（如I/O操作结束、锁被释放）。  
   - 例：磁盘数据读取完成，硬件向CPU发送中断，操作系统将对应的阻塞进程唤醒，放入就绪队列等待调度。

5. **创建态 → 就绪态**  
   - 触发条件：进程初始化完成，系统为其分配完所有必要资源（如PCB、内存）。  
   - 例：用户双击应用程序，操作系统创建进程并完成初始化，进程进入就绪队列。

6. **运行态 → 终止态**  
   - 触发条件：进程完成所有任务（正常退出），或因错误/信号终止（如`kill`命令、程序崩溃）。  
   - 例：进程执行到`exit()`系统调用，或因内存访问错误被操作系统终止。


### 三、状态转换示意图（简化版）
```
创建态 → 就绪态 ←→ 运行态 → 终止态
                 ↓   ↑
                 → 阻塞态 ←
```
- 箭头方向表示状态转换的唯一可能路径（如阻塞态不能直接转换为运行态，必须先到就绪态等待调度）。


### 四、关键说明
- **阻塞态与就绪态的区别**：  
  就绪态进程“万事俱备，只欠CPU”；阻塞态进程“缺少必要条件（如I/O完成），给CPU也无法运行”。  
- **状态转换的核心**：运行态是“中间态”，进程要么在运行，要么在等待运行（就绪），要么在等待事件（阻塞），最终走向终止。  
- **特殊场景**：部分操作系统（如Linux）对状态有更细的划分（如“可中断睡眠”“不可中断睡眠”），但核心逻辑与上述5种状态一致。

理解进程状态转换是掌握操作系统调度机制的基础，也是面试中常考的核心概念。
