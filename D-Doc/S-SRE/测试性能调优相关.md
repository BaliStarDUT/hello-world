# 对 Linux 系统进行 CPU 压力测试
CPU 压测（压力测试）是通过人为制造高 CPU 负载，验证系统在极限或高负载下的稳定性、性能表现和资源调度能力。以下是 **Linux 系统下常用、安全、可控的 CPU 压测方法**。

---

## ✅ 一、常用压测工具（推荐）

### 1. **`stress` / `stress-ng`（最简单易用）**

#### 安装
```bash
# Ubuntu/Debian
sudo apt install stress stress-ng

# CentOS/RHEL
sudo yum install epel-release && sudo yum install stress stress-ng
```

#### 使用示例
```bash
# 占用 4 个 CPU 核心，持续 60 秒
stress --cpu 4 --timeout 60s

# 占用所有 CPU 核心（100%）
stress --cpu $(nproc)

# 更精细控制（stress-ng）
stress-ng --cpu 4 --cpu-method matrixprod --timeout 60s
```
> - `--cpu N`：启动 N 个 worker 进程进行 sqrt() 计算  
> - `stress-ng` 支持多种计算模式（如矩阵乘法、FFT 等），更贴近真实负载

---

### 2. **`sysbench`（数据库/系统综合压测，也支持 CPU）**

#### 安装
```bash
sudo apt install sysbench  # 或 yum install sysbench
```

#### CPU 压测命令
```bash
# 执行素数计算（默认 10000 次）
sysbench cpu --threads=4 --cpu-max-prime=20000 run
```
> - `--threads`：线程数（建议 ≤ CPU 核心数）  
> - `--cpu-max-prime`：计算最大素数，值越大越耗时

---

### 3. **`dd` + `/dev/zero`（简易方法，不推荐用于精确压测）**
```bash
# 利用 gzip 压缩零流，消耗 CPU
dd if=/dev/zero bs=1M count=1000 | gzip -9 >> /dev/null
```
> ⚠️ 缺点：负载不可控，且涉及 I/O，非纯 CPU 压测。

---

### 4. **自定义脚本（Python / Shell）**

#### Python 示例（纯 CPU 密集型）
```python
# cpu_burn.py
import math
import multiprocessing

def burn_cpu():
    while True:
        math.sqrt(123456789)  # 无意义但耗 CPU 的计算

if __name__ == "__main__":
    processes = []
    for _ in range(multiprocessing.cpu_count()):
        p = multiprocessing.Process(target=burn_cpu)
        p.start()
        processes.append(p)

    try:
        for p in processes:
            p.join()
    except KeyboardInterrupt:
        for p in processes:
            p.terminate()
```
运行：
```bash
python3 cpu_burn.py
# 按 Ctrl+C 停止
```

## ✅ 二、监控压测过程

压测时务必监控系统状态：

```bash
# 实时查看 CPU 使用率（按 1 查看每个核心）
top

# 更直观的监控工具
htop

# 查看平均负载
uptime

# 监控特定进程
pidstat -u 1
```

> 📊 关键指标：
> - **%CPU**：是否达到预期（如 100% * 核心数）
> - **load average**：是否远高于 CPU 核心数（可能已过载）
> - **温度/频率**（可选）：`sensors`（需安装 lm-sensors）

## ✅ 三、高级技巧

### 1. **限制压测进程的 CPU 使用（避免系统卡死）**
使用 `cpulimit` 限制单个进程 CPU：
```bash
# 先启动 stress
stress --cpu 2 &
# 获取 PID
PID=$(pgrep stress | head -1)
# 限制该进程最多使用 50% CPU
cpulimit -p $PID -l 50
```

### 2. **绑定 CPU 核心（NUMA 场景）**
```bash
# 只在 CPU 0-1 上运行
taskset -c 0,1 stress --cpu 2
```

### 3. **长时间稳定性压测**
```bash
# 持续压测 1 小时
stress --cpu $(nproc) --timeout 3600s
```

## ⚠️ 注意事项

| 风险 | 建议 |
|------|------|
| **系统无响应** | 避免在生产环境直接压测；预留 SSH 会话；使用 `screen`/`tmux` |
| **过热降频** | 监控温度（`sensors`），确保散热良好 |
| **影响其他服务** | 在测试机或隔离环境中进行 |
| **权限问题** | 普通用户即可运行，无需 root（除非监控系统级指标） |

---

## ✅ 四、压测目标与分析

| 目标 | 如何验证 |
|------|--------|
| **CPU 极限性能** | 观察 `top` 中 %CPU 是否达 100% * 核心数 |
| **系统稳定性** | 压测期间是否出现 OOM、进程崩溃、内核 panic |
| **调度器表现** | 使用 `perf` 分析上下文切换、缓存命中率 |
| **功耗/温度** | 结合硬件传感器数据评估 |

---

## ✅ 总结：推荐流程

1. **准备**：在测试机上安装 `stress-ng` 和 `htop`
2. **执行**：
   ```bash
   stress-ng --cpu $(nproc) --timeout 300s
   ```
3. **监控**：另开终端运行 `htop` 观察 CPU、内存、负载
4. **分析**：记录压测期间系统行为，检查日志（`/var/log/messages`）
5. **清理**：压测自动结束，无需手动 kill

> 💡 **最佳实践**：  
> - 从低负载开始逐步增加  
> - 结合业务场景选择压测模型（如计算密集型 vs 分支预测密集型）  
> - 压测后恢复系统到正常状态

通过以上方法，你可以安全、有效地对 Linux 系统进行 CPU 压力测试。
