线程是操作系统调度的基本单位（比进程更轻量，共享进程资源），其状态会随调度、资源获取/释放、任务执行等行为动态变化。不同操作系统（如Linux、Windows）对线程状态的定义略有差异，但核心逻辑一致，通常可归纳为**6种核心状态**，以下结合通用模型和Java线程状态（最具代表性）展开介绍：


### 一、线程的6种核心状态（通用+Java对应）
线程状态的本质是“线程当前的可执行性”，不同状态对应“是否能被CPU调度”“是否在等待资源”等核心特征。下表对比通用状态与Java线程状态（Java通过`Thread.State`枚举定义，是面试高频考点）：

| 通用状态         | Java对应状态          | 核心含义                                                                 |
|------------------|-----------------------|--------------------------------------------------------------------------|
| 新建态（New）    | `NEW`                 | 线程对象已创建，但未调用`start()`方法，未进入操作系统调度队列。           |
| 就绪态（Runnable）| `RUNNABLE`           | 线程已调用`start()`，进入操作系统就绪队列，**具备被CPU调度的条件**（可能正在运行，也可能等待CPU）。 |
| 阻塞态（Blocked） | `BLOCKED`             | 线程因**等待锁资源**（如`synchronized`锁）而暂停，无法被CPU调度。         |
| 等待态（Waiting） | `WAITING`             | 线程因主动调用无超时等待方法（如`wait()`、`join()`），无限期等待被唤醒，无CPU调度资格。 |
| 超时等待态（Timed Waiting） | `TIMED_WAITING` | 线程因调用有超时等待方法（如`sleep(1000)`、`wait(5000)`），在超时前等待，无CPU调度资格。 |
| 终止态（Terminated） | `TERMINATED`        | 线程任务执行完毕（正常退出）或因异常终止，资源被回收，无法再恢复。         |


### 二、线程状态转换过程（核心触发条件）
线程状态转换由**操作系统调度**（如CPU分配）、**线程间协作**（如锁竞争、唤醒）、**自身API调用**（如`sleep()`）共同触发，以下是关键转换路径及示例：

#### 1. 新建态（New）→ 就绪态（Runnable）
- **触发条件**：调用线程对象的`start()`方法（而非`run()`方法，`run()`仅执行任务逻辑，不触发调度）。  
- **原理**：`start()`会向操作系统注册线程，将其加入就绪队列，等待CPU调度。  
- **示例**：  
  ```java
  Thread t = new Thread(() -> System.out.println("线程任务")); 
  t.start(); // 调用后，t从NEW转为RUNNABLE
  ```


#### 2. 就绪态（Runnable）→ 运行中（Runnable的子集）
- **触发条件**：操作系统调度程序从就绪队列中选择线程，分配CPU时间片。  
- **说明**：Java的`RUNNABLE`状态包含“正在运行”和“等待CPU”两种情况（因Java不区分“就绪”和“运行”的底层细节，统一归为`RUNNABLE`）；通用模型中“就绪态→运行态”的本质就是CPU调度。  
- **示例**：多个`Runnable`线程中，CPU通过“时间片轮转”或“优先级调度”选择一个执行，该线程进入实际运行。


#### 3. 运行中（Runnable）→ 阻塞态（Blocked）
- **触发条件**：线程竞争**对象锁**失败（如进入`synchronized`代码块，但锁已被其他线程持有）。  
- **原理**：锁竞争失败的线程会被放入“锁等待队列”，暂时失去CPU调度资格，直到锁被释放并重新竞争成功。  
- **示例**：  
  ```java
  Object lock = new Object();
  Thread t1 = new Thread(() -> {
      synchronized (lock) { // t1获取锁，进入运行
          try { Thread.sleep(1000); } catch (InterruptedException e) {}
      }
  });
  Thread t2 = new Thread(() -> {
      synchronized (lock) { // t2竞争锁失败，从RUNNABLE转为BLOCKED
          System.out.println("t2获取锁");
      }
  });
  t1.start();
  t2.start(); // t2会进入BLOCKED状态，直到t1释放锁
  ```


#### 4. 运行中（Runnable）→ 等待态（Waiting）
- **触发条件**：线程主动调用**无超时等待方法**，主动放弃CPU，无限期等待被其他线程唤醒。  
  常见方法：  
  - `Object.wait()`（需在`synchronized`块中调用，释放对象锁）；  
  - `Thread.join()`（等待目标线程执行完毕，无超时）；  
  - `LockSupport.park()`（无参数版本，暂停当前线程）。  
- **示例**：  
  ```java
  Object lock = new Object();
  Thread t = new Thread(() -> {
      synchronized (lock) {
          try {
              lock.wait(); // t调用wait()，释放锁，从RUNNABLE转为WAITING
          } catch (InterruptedException e) {}
      }
  });
  t.start();
  ```


#### 5. 运行中（Runnable）→ 超时等待态（Timed Waiting）
- **触发条件**：线程调用**有超时等待方法**，在指定时间内等待，超时后自动唤醒。  
  常见方法：  
  - `Thread.sleep(long millis)`（暂停线程，**不释放锁**）；  
  - `Object.wait(long timeout)`（释放对象锁，超时后自动唤醒）；  
  - `Thread.join(long millis)`（等待目标线程，超时后不再等待）；  
  - `LockSupport.parkNanos(long nanos)`（超时暂停）。  
- **关键区别**：与`Waiting`的核心差异是“是否有超时机制”——`Timed Waiting`无需手动唤醒，超时后会自动恢复就绪态；`Waiting`必须依赖其他线程调用`notify()`/`notifyAll()`唤醒。  
- **示例**：  
  ```java
  Thread t = new Thread(() -> {
      try {
          Thread.sleep(2000); // t从RUNNABLE转为TIMED_WAITING，2秒后自动唤醒
      } catch (InterruptedException e) {}
  });
  t.start();
  ```


#### 6. 阻塞态/等待态/超时等待态 → 就绪态（Runnable）
这三类“非就绪态”线程需通过特定条件唤醒，重新获得CPU调度资格：
| 原状态         | 唤醒条件                                                                 |
|----------------|--------------------------------------------------------------------------|
| Blocked        | 持有锁的线程释放锁（如退出`synchronized`块），当前线程重新竞争锁成功。     |
| Waiting        | 其他线程调用`Object.notify()`/`notifyAll()`（对应`wait()`），或目标线程执行完毕（对应`join()`）。 |
| Timed Waiting  | 等待超时（如`sleep(2000)`到时间），或被其他线程中断（调用`interrupt()`）。 |
- **示例**：唤醒`Waiting`状态的线程：  
  ```java
  // 延续步骤4的代码，主线程唤醒t
  synchronized (lock) {
      lock.notify(); // 调用后，t从WAITING转为RUNNABLE
  }
  ```


#### 7. 运行中（Runnable）→ 终止态（Terminated）
- **触发条件**：  
  1. 线程任务正常执行完毕（`run()`方法执行结束）；  
  2. 线程因未捕获异常终止（如`NullPointerException`）；  
  3. 其他线程调用`Thread.stop()`（已废弃，会强制终止线程，可能导致资源泄漏）。  
- **说明**：终止态的线程无法再恢复（即使调用`start()`也会抛出`IllegalThreadStateException`）。  
- **示例**：  
  ```java
  Thread t = new Thread(() -> {
      System.out.println("任务执行"); // 执行完毕后，t从RUNNABLE转为TERMINATED
  });
  t.start();
  ```


### 三、线程状态转换示意图（Java模型）
```
NEW → (start()) → RUNNABLE ←(唤醒/超时)← BLOCKED
                          ↖←(唤醒)← WAITING
                          ↖←(超时/中断)← TIMED_WAITING
                          ↓(任务完成/异常)
                          TERMINATED
```
- 核心规则：**只有`NEW`状态的线程能调用`start()`**，`TERMINATED`状态的线程无法再转换，其他非就绪态（Blocked/Waiting/Timed Waiting）必须先回到`RUNNABLE`，才能被CPU调度。


### 四、关键概念辨析
1. **Runnable与Running的关系**：  
   通用模型中“就绪态”和“运行态”是两个独立状态，但Java将其合并为`RUNNABLE`（因Java不暴露底层CPU调度细节，只关心“是否可被调度”）。

2. **Blocked与Waiting的区别**：  
   - `Blocked`：等待**锁资源**（被动等待，无需手动唤醒，锁释放后自动竞争）；  
   - `Waiting`：等待**线程协作信号**（主动调用`wait()`/`join()`，必须手动唤醒）。

3. **sleep()与wait()的区别**：  
   - `sleep(long)`：不释放锁，属于`Timed Waiting`，超时后自动唤醒；  
   - `wait()`：释放对象锁，属于`Waiting`，必须通过`notify()`唤醒。


理解线程状态转换是掌握多线程编程的基础，尤其在并发问题排查（如死锁、线程阻塞）和面试中（高频考点：Java线程状态、状态转换触发条件）至关重要。
